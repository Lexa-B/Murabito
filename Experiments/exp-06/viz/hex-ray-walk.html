One hex, one ray: which face does it leave through?

Everything in cube coordinates (q, r, s), q + r + s = 0, with the main branch's directions: +q is east, anticlockwise from there. Drag the origin (filled dot) anywhere inside the cell and the direction (open dot) anywhere at all.

facee = (dq, dr, ds)planee · dt to its plane

The rule, for the face toward the neighbour at cube offset e, cell centre c, ray o + t·d:

v = e · d                      // moving toward this face? (v ≤ 0: not a candidate)
t = (1 − e · (o − c)) / v      // the face is the plane e · (p − c) = 1
exit = the candidate with the smallest t

Plain three-component dot products in (q, r, s): one per face, and one division per candidate. The cell itself is the three slabs |Δq − Δr| ≤ 1, |Δq − Δs| ≤ 1, |Δr − Δs| ≤ 1. A tie between two faces means the ray passes through their shared corner; either neighbour is a correct next cell.

Bite two: across the face and on

The same ray, now walking. Drag the origin anywhere in the patch and the direction anywhere. The start cell is cube_round(o), the crate's VoxelspacePos::round. Each step crosses the nearest candidate plane, moves the centre by that face's e, and nudges the three t values instead of recomputing them.

candidates: the three faces with v = e · d > 0, and their 1/v     // fixed for the ray
c = cube_round(o);  t_j = (1 − e_j · (o − c)) / v_j                 // bite one
loop:
    i = the candidate with the smallest t              // exit face
    ... the cell c is visited from t_in to t_i ...
    c += e_i                                            // step into the neighbour
    t_i += 2 / v_i                                      // that family: a whole cell on
    t_j += (e_j · e_i) / v_j   for the other two        // e_j · e_i is +1 or −1: half a cell
    t_in = t_i
#cell (q, r, s)t inexitt out

The last three columns are the incremental t values while in that cell, each with the nudge it received on entering. The summary line checks them against bite one's direct formula recomputed in every cell: the two should agree to floating-point noise.

Bite three: the vertical

A voxel is a layer thick: layer = y / 0.5, and voxel L is [L, L+1). The layer planes sit at every integer, in every column, so they are one global stack: the video's case exactly, with no nudging. The ray gets a fourth candidate, t_y, and each step takes the smallest of four.

t_y    = (next integer layer along d − o_layer) / d_layer   // ∞ when d_layer = 0
step_y = 1 / |d_layer|                                       // fixed for the ray
loop:
    if t_y < min(t_hex):                                      // out through a cap
        visit (c, layer) until t_y;   layer += sign(d_layer);   t_y += step_y
    else:                                                     // out through a face
        visit (c, layer) until t_i;   c += e_i;   nudge the three hex t (bite two)
#voxel (q, r, s | layer)t inexitt out

The two families never touch: a cap crossing changes layer and t_y only, a face crossing changes c and the three hex t only. The section is eight layers tall and the ray stops at the patch edge or at the top or bottom, whichever comes first.

Bite four: the columns are runs

Now the patch has ground in it. A column is stored the way the second video stores it: a list of (material, height) from the bottom up, and for lookup the run tops, so run k covers layers [top[k−1], top[k]). The same ray as bite three, with the same controls, now walks runs instead of layers: an air run is one step however tall it is, and the first solid run it reaches is the hit.

on entering a column at t_in:
    k = the run holding layer(t_in)                        // a scan of three to six entries
    loop:
        if run[k] is solid:  HIT at t_in, through the face or cap just crossed
        boundary = climbing ? top[k] : top[k−1]             // where this air run ends, my way
        t_b = (boundary − o_layer) / d_layer                // one division; ∞ when d_layer = 0
        if t_b ≥ t_out:  leave the column, one step for the whole run
        else:            t_in = t_b;  k += sign(d_layer)    // next run up or down; off the ends is sky or bedrock
#columnrunt inexitt out
 

  

  
Compared with bite three, the vertical family has changed character: t_y is no longer the next integer layer at a fixed stride, it is the next run boundary, one division per boundary. The hex family is untouched. The cost of a column is now the number of runs the ray passes through, not the number of layers, and the block of data above is the whole of what the shader needs to read for that column.


  
Bite five: skipping columns

  
Skimming over open ground, bite four still spends a step on every column. To jump several at once the ray needs one coarser fact per group of columns: hi(P), the top of the highest solid run in the group. If the ray is at or above hi(P) where it enters the group and where it leaves, nothing in there can be under it, and the whole span is one step. The groups are the hex hierarchy: a parent cell is the same lattice scaled by k (exp-05's ken is k = 6; here k = 3 so several fit the picture), so the parent walk is bite two's walk with o and d divided by k, and its t values are the same numbers. Same controls; a wider, gentler patch so there is sky to skim through.


  


  


parents: bite two's walk on the parent lattice, o/k and d/k          // same t values
for each parent P the ray crosses, from t_in to t_out:
    if layer(t_in) ≥ hi(P) and layer(t_out) ≥ hi(P):                    // nothing can be under the ray in here
        one step: t = t_out
    else:
        bite four across the fine columns from t to t_out, then back up  // hit, or the parent's far boundary

hi(P) = max top of any solid run in any cell whose hexagon overlaps P's  // owned or straddling, so a skip is always safe

The same test runs the other way for caves, with a lo(P) under which a ray below everything solid can skip; it is the same idea and is left out of the picture. Deeper hierarchies stack the same step: a grandparent at k² with its own hi, checked first.


  
Bite six: the nesting

  
Packing B, from exp-03: parent (a, b) is centred on child (N·a, N·b), and a child belongs to the nearest parent centre by d² = dq² + dq·dr + dr², ties to the lexicographically greatest (a, b). It works for any N. Drag N and watch the battlements; the centre parent's owned children are counted live against N².


  

    

      
    

    

      

      

      
Tints are the seven parents nearest the centre; heavy outlines are their ideal hexagons, which the owned territory follows with battlement edges. A parent's corner is at N·(2/3, −1/3, −1/3): a child centre when 3 | N, hence the three-way corner children at 6, 60 and 36; a child corner otherwise, so at 10 the corners are clean and only edge children are halved.

Bite seven: fine and coarse are relative

  
No level is the fine one. Detail at level k is held throughout a window round the camera, and outside that window the level above is the surface the ray hits. The candidate rule: level k detail fills the camera's level k+2 cell, its grandparent: shaku columns across the decichō the camera is in, ken columns across its chō, decichō columns across its ri. Drag the camera (the dot) in either panel; the panels share it. Pick the window's shape below.

"A cell at that edge" is the angular width of one level-k cell seen at the window's nearest edge, and its width in pixels at 1080p with a 60° field of view: the size of the step a viewer sees where detail drops a rung. The walk gains one branch over bite five: at every level a cell is skipped (hi clears the ray), descended into (a finer level is resident here), or hit (nothing finer is resident, so this column is the surface). Skip structure and distance detail are one thing, and residency alone decides which a cell is right now.
