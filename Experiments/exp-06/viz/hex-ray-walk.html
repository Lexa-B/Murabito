One hex, one ray: which face does it leave through?

Everything in cube coordinates (q, r, s), q + r + s = 0, with the main branch's directions: +q is east, anticlockwise from there. Drag the origin (filled dot) anywhere inside the cell and the direction (open dot) anywhere at all.

facee = (dq, dr, ds)planee · dt to its plane

The rule, for the face toward the neighbour at cube offset e, cell centre c, ray o + t·d:

v = e · d                      // moving toward this face? (v ≤ 0: not a candidate)
t = (1 − e · (o − c)) / v      // the face is the plane e · (p − c) = 1
exit = the candidate with the smallest t

Plain three-component dot products in (q, r, s): one per face, and one division per candidate. The cell itself is the three slabs |Δq − Δr| ≤ 1, |Δq − Δs| ≤ 1, |Δr − Δs| ≤ 1. A tie between two faces means the ray passes through their shared corner; either neighbour is a correct next cell.

Bite two: across the face and on

The same ray, now walking. Drag the origin anywhere in the patch and the direction anywhere. The start cell is cube_round(o), the crate's VoxelspacePos::round. Each step crosses the nearest candidate plane, moves the centre by that face's e, and nudges the three t values instead of recomputing them.

candidates: the three faces with v = e · d > 0, and their 1/v     // fixed for the ray
c = cube_round(o);  t_j = (1 − e_j · (o − c)) / v_j                 // bite one
loop:
    i = the candidate with the smallest t              // exit face
    ... the cell c is visited from t_in to t_i ...
    c += e_i                                            // step into the neighbour
    t_i += 2 / v_i                                      // that family: a whole cell on
    t_j += (e_j · e_i) / v_j   for the other two        // e_j · e_i is +1 or −1: half a cell
    t_in = t_i
#cell (q, r, s)t inexitt out

The last three columns are the incremental t values while in that cell, each with the nudge it received on entering. The summary line checks them against bite one's direct formula recomputed in every cell: the two should agree to floating-point noise.
